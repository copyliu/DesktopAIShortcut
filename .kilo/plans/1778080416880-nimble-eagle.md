## Step 1: OpenAIAdapter 增加流式方法
**文件**: `DesktopAIShortcut/Adapter/OpenAIAdapter.cs`

新增方法 `SendMessageStreamingAsync`：
```csharp
public async Task SendMessageStreamingAsync(
    List<ChatMsgViewModel> request,
    Action<string> onTextChunk,
    Action<string>? onReasoningChunk = null)
```

**实现要点**:
- 调用 `client.CompleteChatStreamingAsync()`（OpenAI SDK 2.8.0 支持）
- 遍历 `AsyncCollectionResult<StreamingChatCompletionUpdate>` 异步枚举
- 从 `update.ContentUpdate` 提取文本增量 → `onTextChunk(text)`
- 检查 `StreamingChatCompletionUpdate` 中是否有 reasoning / thinking 相关字段（如 `ReasoningTokenDelta` 或通过 reflection 检查），若有则回调 `onReasoningChunk`
- 用 try/catch 包裹，异常通过回调传出

## Step 2: ChatMsgViewModel 增加思考内容支持
**文件**: `DesktopAIShortcut/ViewModels/ChatMsgViewModel.cs`

**新增属性**:
| 属性 | 类型 | 说明 |
|------|------|------|
| `Reasoning` | `string` | 思考过程文本 |
| `ReasoningBuilder` | `ObservableStringBuilder` | 思考过程的 LiveMarkdown builder |

| `IsThinking` | `bool` | 是否正在思考中 |

**新增方法**: `AppendReasoning(string text)` — 追加思考内容到 `ReasoningBuilder`

## Step 3: 修改 AddUserMessageAsync 使用流式调用
**文件**: `DesktopAIShortcut/ViewModels/ChatHistoryViewModel.cs`

**改动**:
- 创建 response 后不再调用 `adap.SendMessageAsync`，改为 `SendMessageStreamingAsync`
- 文本回调：`response.AppendText(text)` — 直接追加到 MarkdownStringBuilder，LiveMarkdown 实时渲染
- 思考回调：`response.AppendReasoning(text)` — 追加到 ReasoningBuilder，UI 实时显示
- 开始前设置 `response.IsThinking = true`，文本首次到达时设为 `false`
- try/catch 中保留错误消息写入 `response.Markdown`

## Step 4: ChatMsgControl UI 增加思考区域 + 操作按钮
**文件**: `DesktopAIShortcut/ChatMsgControl.axaml`

**UI 结构变更** (针对非用户消息，即 `Role != User`):
```
DockPanel
├── Label (UserName)
├── Expander "思考过程"         ← 新增：绑定 IsThinking/HasReasoning 控制显隐
│   └── MarkdownRenderer       ← 绑定 ReasoningBuilder
├── Border
│   └── MarkdownRenderer       ← 已有：绑定 MarkdownStringBuilder
└── StackPanel (操作按钮)      ← 新增：水平排列的按钮组
    ├── Button "复制Markdown"
    ├── Button "复制全文"
    └── Button "重新生成"
```

**文件**: `DesktopAIShortcut/ChatMsgControl.axaml.cs`

**新增事件处理**:
| 按钮 | 逻辑 |
|------|------|
| 复制Markdown | `Clipboard.SetTextAsync(viewModel.Markdown)` |
| 复制全文 | `Clipboard.SetTextAsync(Markdown.ToPlainText(viewModel.Markdown))`，使用 Markdig 库（已引入） |
| 重新生成 | 从父级 Messages 中移除当前消息及其之前的用户消息，触发重新调用 AI。通过查找 ItemsControl 祖先获取 ChatHistoryViewModel 引用 |

**重新生成实现方案**:
- ChatMsgControl 需要回调到所属的 ChatHistoryViewModel
- 在 ChatHistoryViewModel 上新增 `RegenerateLastResponse` 方法：
  1. 找到最后一条 assistant 消息的索引
  2. 移除该 assistant 消息
  3. 将倒数第二条 user 消息的 Markdown 作为 UserInput 重新发送
  4. 调用 AddUserMessageAsync（但跳过添加新 user 消息）
- ChatMsgControl 通过 `RelativeSource AncestorType` 绑定或代码查找父级 DataContext

## 边界与兼容性
- **无网络/API 错误**: 流式回调异常时，写入错误消息到 Markdown
- **无思考内容的模型**: onReasoningChunk 为 null 时不调用，UI 不显示思考区域
- **用户消息**: 不显示操作按钮和思考区域（仅对 `Role != User` 显示）
- **旧版聊天记录加载**: Reasoning 字段为 null，UI 应正确处理
